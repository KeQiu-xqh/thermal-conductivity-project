# 项目计划

> 更新日期：2026-04-25

## 我为什么创建这个仓库

这个仓库用于持续记录和推进一个基于以下链路的金属导热实验项目：

- Raspberry Pi 5
- Thermal-90 红外热像模块
- 原始热像数据 `.dat` 采集
- 本地回看、可视化与 ROI 分析
- 训练数据构建
- 后续 PINN / 反演求取导热相关参数

这个项目的目标不是单纯“把相机跑起来”，而是逐步形成一条可重复的实验流程：

1. 稳定采集热像数据
2. 规范整理原始数据与实验记录
3. 从固定样品 ROI 构建训练数据
4. 为后续导热系数反演做准备

## 本仓库将记录什么

本仓库主要记录以下内容：

- 树莓派与 Thermal-90 的实验使用流程
- 热像原始数据采集与回传方法
- Windows 本地回看与分析脚本
- ROI 选择、数据格式整理与训练数据构建流程
- 实验阶段决策、问题修复和下一步动作
- 正式实验前的样品、加热方式与数据规范化准备

## 当前确认的结论

- 采集链路已经不是主要风险点。
- 当前训练数据中的 ROI 仍然是“候选 ROI”，不是最终正式样品的物理 ROI。
- 当前项目已经具备做“热像测温稳定性与局部区域可观测性验证”的条件。
- 当前项目还不具备直接输出最终导热系数结论的条件，仍需要继续规范实验布置与数据格式。

## 接下来要完成的任务

### 第一部分：固定正式实验布置

- 固定相机位置、样品位置、加热源位置
- 优先围绕金属丝 / 金属细杆样品建立正式实验视野
- 停止把“热点候选区”直接当作最终物理 ROI
- 让后续每次采集都尽量在同一视角和同一布局下进行

### 第二部分：规范原始数据与实验记录

- 统一原始数据命名规则，例如 `thermal90-YYYYMMDD-runNN.dat`
- 每次实验同步记录样品、加热方式、文件名和备注
- 将原始数据固定放入 `data/raw/`
- 将派生结果固定放入 `data/derived/`、`outputs/preview/`、`outputs/figures/`

### 第三部分：收敛训练数据格式

- 基于正式样品 ROI 重新构建训练数据
- 继续审查当前 `x, y, t -> T` 格式是否过于宽泛
- 评估是否需要压缩、投影或重组为更适合 1D 导热反演的表示
- 保留足够元信息，确保训练数据与实验条件可追溯

### 第四部分：为 PINN / 反演阶段做准备

- 梳理边界条件、初始条件与样品几何信息
- 明确像素坐标、时间轴和温度场之间的对应关系
- 在数据质量稳定后，再进入 PINN 训练与导热参数反演
- 后续根据材料参数关系，将反演得到的热扩散率进一步换算为导热率

## 当前优先级

如果只做最重要的几件事，优先顺序应为：

1. 固定正式样品 ROI
2. 统一原始数据命名和实验记录
3. 重新生成更规范的训练数据
4. 再进入 PINN / 导热反演主线

## 现在不应该误判的地方

- 不要把“已经能录制热像”误认为“已经能做正式导热率测量”
- 不要把当前候选 ROI 当作最终物理样品 ROI
- 不要在实验布置仍不稳定时就提前进入反演结论阶段
- 不要把仓库首页和项目计划继续写成“树莓派入门搭建记录”，这已经不是当前主线
