# 07-实验流程操作手册
> 日期：2026-04-24
> 适用场景：从零开始，把树莓派、VNC、Thermal-90、数据采集和本地回看完整跑一遍。  
> 使用原则：按顺序做，不临场回忆，不跳步骤。  
> 当前主线：**智能加热平台 + 金属丝/金属细杆样品 + Thermal-90 热像采集**

---

## 一、基础问题

1. **SSH 终端**和**VNC 桌面**不是一回事。
   - SSH：适合登录、查状态、跑不需要图形界面的命令。
   - VNC：适合运行需要显示窗口的程序，比如实时热像可视化。

2. 如果程序报：
   - `could not connect to display`
   - `Could not load the Qt platform plugin "xcb"`
   
   这通常是因为在 **SSH 终端里跑了需要图形界面的程序**。这时要改到 **VNC 桌面终端**里运行。

3. 当前项目已经不是“能不能采到”的阶段，而是：
   - 固定正式样品位置
   - 固定 ROI
   - 采一组命名规范、可分析的数据

4. 今天不要把“候选热区 ROI”直接当成“最终物理样品 ROI”。

---

## 二、实验流程总览

1. 连接硬件并给树莓派上电
2. 用电脑连上同一热点/同一局域网
3. SSH 登录树莓派，确认在线
4. 打开 VNC，进入树莓派桌面
5. 在 SSH 里做基础检查
6. 在 VNC 桌面终端里跑实时热像，确认画面正常
7. 摆好样品、热源、相机位置
8. 录制 `.dat` 原始热像数据
9. 把 `.dat` 从树莓派拷回 Windows
10. 在 Windows 本地生成 GIF 和预览图
11. 记录本次实验文件名、样品和备注
12. 安全关机

## 三、实验开始前的硬件检查

### 1. 先检查这些东西是否齐全

- Raspberry Pi 5
- Thermal-90 Camera HAT
- microSD 卡
- 树莓派电源
- 电脑
- 手机热点或可控局域网
- 金属丝 / 金属细杆样品
- 智能加热平台
- 固定样品的位置夹具或支撑

### 2. 上电前检查

- 确认 Thermal-90 已经正确接在树莓派 GPIO 上
- 确认 microSD 卡已插入
- 确认样品和加热平台暂时不要乱放到镜头前，先把系统跑通

## 四、连接树莓派

### 1. 网络连接

- 打开手机热点（推荐）
- 让电脑连接这个热点
- 给树莓派上电，让树莓派也连接到这个热点
- 在热点设备列表里找到树莓派 IP

> 推荐热点而不是复杂校园网，因为更容易看到已连接设备和 IP。

### 2. 在 Windows PowerShell 登录树莓派

在电脑的 PowerShell 输入：

```bash
ssh piqio@树莓派IP地址
```


### 3. 如果第一次 SSH 失败

如果出现：

```text
Connection closed by ... port 22
```

先不要慌，按这个顺序处理：

1. 等 20 到 30 秒
2. 再重新输一次同样的 SSH 命令
3. 还不行再检查树莓派是否刚启动、IP 是否变化

## 五、登录后先做 30 秒基础检查

在 SSH 终端里依次输入：

```bash
whoami
hostname
pwd
python3 --version
ls /dev/i2c*
ls /dev/spidev*
```
看到的是：

- 当前用户是 `piqio`
- 能正常显示当前目录
- Python 3 可用
- 能看到 I2C 和 SPI 设备节点

### 4. 关键检查：I2C 总线

继续输入：

```bash
i2cdetect -l
sudo i2cdetect -y 1
```

希望看到：

- 存在 `/dev/i2c-1`
- `i2cdetect -y 1` 能扫到 `0x40`

如果这里不对，就不要急着跑采集程序。

### 12. 成功标志

看到两类现象：

- 终端持续输出 `FID / Min / Max / Avg / Std`
- VNC 桌面里能看到实时热像窗口

如果只输出日志，没有图像，检查你是不是在 SSH 而不是 VNC 里运行。

### *问题： 如果程序卡住或没继续出帧

先这样处理：

1. `Ctrl + C` 停掉
2. 等 5 到 10 秒
3. 再重新运行一次

项目记录里已经出现过“进入连续模式后偶发卡在第一帧前”的情况，所以偶发重试并不说明系统完全坏了。

## 九、正式摆放样品前，先固定 3 个位置

在开始录制正式数据前，先固定：

1. 相机位置
2. 样品位置
3. 热源位置

### 具体要求

- 相机不要手持，尽量固定
- 样品尽量沿画面某个明确方向摆放，后面才容易做 1D 导热分析
- 热源位置保持固定，不要每次靠手感挪
- 样品尽量完整进入视野，不要贴边

### 今日建议

- 正式路线优先：金属丝 / 金属细杆
- 金属片只作为热像调试或兜底

## 十、开始录制原始数据

### 13. 进入录制目录

在 VNC 终端里：

```bash
cd ~/thermal90/pysenxor-master/example
```

### 14. 开始录制

```bash
sudo python3 stream_spi.py -r
```

也可以是

```bash
cd ~/experiment/code
sudo python3 thermal90_ir_temp.py -r
```

#### 录制时你要做什么

- 先确认程序已经稳定出帧
- 再开始加热或把样品放到正式位置
- 保持相机和样品不要再晃动
- 录制够一段完整过程后停止

#### 停止录制

按：

```text
Ctrl + C
```

正常结束时应看到类似：

```text
INFO:__main__:Exiting due to SIGINT or SIGTERM
INFO:__main__:Done.
```

### 15. 检查 `.dat` 是否生成

```bash
ls -lh *.dat
```
如果你想全局找最近生成的录制文件：
```bash
find ~ -name "*.dat" -printf "%T@ %p\n" | sort -n | tail
```
记下最新生成的文件名。

> 以后建议统一命名到项目数据目录，例如 `thermal90-YYYYMMDD-runNN.dat`。  
> 但如果今天还是官方默认文件名，也没关系，先保证数据采下来。

## 十七、遇到问题时怎么快速判断

### 1. 能 SSH，不能看图

- 原因大概率是你没在 VNC 桌面终端里运行图形程序
- 处理：改到 VNC 里跑

### 2. 找不到 `/dev/i2c-1`

- 先不要急着改 Python 代码
- 先检查 `i2c_arm` 是否开启、系统是否正常启动

### 3. `i2cdetect -y 1` 扫不到 `0x40`

- 先检查相机硬件连接
- 检查供电
- 检查 GPIO 连接是否松动

### 4. 录完的文件不能双击直接看视频

- 这是正常的
- `.dat` 不是 mp4
- 要用 `python code/view_dat.py` 生成 GIF 回看

### 5. 热区看起来在变，但 ROI 不稳定

- 这说明现在更该做的是固定样品和相机位置
- 不是马上进入导热系数反演

## 十八、今天建议你实际执行的版本

如果你今天只是要“从零到完整跑通一遍”，按这个最小版本做：

2. `ssh piqio@IP`

10. `scp` 拷回 `.dat`

12. 看 GIF 和曲线
13. 记下本次文件名和问题
14. `sudo shutdown now`
